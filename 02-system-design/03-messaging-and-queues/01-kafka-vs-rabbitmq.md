# System Design Урок 3: Брокери повідомлень (Kafka vs RabbitMQ)

## 1. Навіщо потрібні черги?
- **Асинхронність:** Відв'язка важких операцій (наприклад, генерація звітів чи відправка email) від основного потоку запиту користувача.
- **Буферизація (Load Leveling):** Захист бекенду від пікових навантажень (Flash Sales).
- **Декуплінг (Decoupling):** Незалежність мікросервісів один від одного.

## 2. RabbitMQ vs Apache Kafka
| Критерій | RabbitMQ | Apache Kafka |
| :--- | :--- | :--- |
| **Архітектура** | Smart broker, dumb consumer (маршрутизація через exchanges). | Dumb broker, smart consumer (зберігання логів у партиціях). |
| **Зберігання** | Видаляє повідомлення після підтвердження (ACK). | Зберігає лог повідомлень на диск протягом заданого часу (retention period). |
| **Пропускна здатність** | Середня (десятки тисяч повідомлень/сек). | Висока (мільйони повідомлень/сек). |
| **Використання** | Черги завдань, RPC, складна маршрутизація. | Event streaming, логування, аналітика в реальному часі. |
