# System Design Урок 5: Розподілені патерни

## 1. Rate Limiting (Обмеження частоти запитів)
Захищає систему від перевантаження та зловживань.
- **Token Bucket:** У "відрі" з токенами, який поповнюється з певною швидкістю. Кожен запит забирає токен. Якщо токенів нема — 429 (Too Many Requests).
- **Leaky Bucket:** Запити надходять, але обробляються з фіксованою швидкістю (вирівнювання потоку).
- **Fixed / Sliding Window:** Лічильник запитів у часовому вікні.

## 2. Circuit Breaker (Розривне коло)
Патерн для запобігання каскадним збоям. Має 3 стани:
1. **Closed:** Звичайний режим, запити проходять.
2. **Open:** Після N невдач коло "розривається", запити одразу падають без звернення до зламаного сервісу.
3. **Half-Open:** Пробні запити для перевірки відновлення.

## 3. Consistent Hashing (Узгоджене хешування)
Використовується для розподілу даних у кешах/шардах. Кільце хешів дозволяє додавати/видаляти вузли, мінімізуючи обсяг даних, що потрібно перемістити.

## 4. Розподілені блокування (Distributed Locks)
Блокування ресурсу між різними серверами. Реалізації: Redis (Redlock), etcd, ZooKeeper. Потрібні для узгодженості у мікросервісах.
