# Кейс-студії System Design

Кожен кейс — це шаблон відповіді на співбесіді. Структура: Вимоги → Оцінка масштабу → API → Схема даних → Високорівнева архітектура → Деталізація → Вузькі місця.

## 1. Design URL Shortener (TinyURL)
**Вимоги:** Скорочення довгих URL, редирект, кастомні аліаси, аналітика.
**Оцінка:** 100M нових URL/місяць, читання >> запис (100:1).
**Алгоритм генерації:** Base62 кодування автоінкрементного ID або хеш + розв'язання колізій.
**Архітектура:** 
- **Write path:** Сервер → генерація короткого ключа → збереження в БД → повернення.
- **Read path:** Кеш (Redis) для найпопулярніших + шардована БД.
**Ключова деталь:** 301 (permanent) для кешування на боці CDN/браузера vs 302 (temporary) для збереження аналітики.

## 2. Design Twitter / News Feed
**Проблема:** Fan-out на мільйони підписників.
- **Pull model:** Читання твітів підписок на льоті (складно при запиті).
- **Push model (Fan-out on write):** Запис твіта розсилається у фіди всіх підписників.
- **Гібрид (реальність Twitter):** Push для звичайних акаунтів, Pull для зірок із мільйонами фоловерів.

## 3. Design Chat System (WhatsApp / Slack)
**Вимоги:** Один-на-один та групові чати, статус онлайн, історія, push.
**Архітектура:** WebSocket-з'єднання для реального часу, Presence Service для онлайн-статусів, база для історії, гарантії доставки через ACK.

## 4. Design Uber / Ride Sharing
**Головна складність:** Nearby Drivers — геопростір (geospatial) пошук.
**Рішення:** Геохеші (geohash) або geospatial індекс (Redis GEO, S2 Geometry), щоб знаходити водіїв у радіусі водія.

## 5. Design YouTube / Video Streaming
**Виклики:** Величезні відеофайли та трафік.
**Архітектура:** Транскодування відео в різні якості (adaptive bitrate), роздача через CDN (Content Delivery Network), cold storage для архівів.
