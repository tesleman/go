# Урок 1: Базові типи, змінні та колекції у Go

## 1. Змінні та константи
У Go статична типізація. Змінні оголошуються за допомогою ключового слова `var` або короткого оператора оголошення `:=` (аналог `let` в TS, але з жорсткою перевіркою типу).

```go
package main

import "fmt"

func main() {
    // Явне оголошення (аналог let name: string = "Go")
    var name string = "Go"
    var age int = 15

    // Коротке оголошення (аналог const version = 1.22)
    version := 1.22
    isAwesome := true

    fmt.Printf("Language: %s, Age: %d, Version: %.2f, Awesome: %t\n", name, age, version, isAwesome)
}
```

> **Від JS/TS:** У Go немає `var` без типу. `:=` виводить тип автоматично (як TS), але змінити тип змінної пізніше неможливо. У TS `let x = 5` можна переприсвоїти як рядок — у Go ні.

## 2. Зрізи (Slices) — аналог JS масивів
Зріз у Go — це динамічне вікно у базовий масив (backing array). Він складається з трьох елементів:
1. **Вказівник** на перший елемент базового масиву.
2. **Довжина (Length)** — кількість елементів (`len()`).
3. **Місткість (Capacity)** — максимальна кількість елементів (`cap()`).

```go
s := make([]int, 3, 5) // len = 3, cap = 5
s = append(s, 10)      // Додавання елемента (аналог .push(10))
```

> **Від JS:** JS-масиви (`Array<T>`) автоматично ресайзяться. Go slices теж, але під капотом — виділення нового масиву коли перевищується `cap`. Це як JS `Array`, але з явним контролем ємності. У TS/JS `.push()` повертає нову довжину, Go `append()` повертає новий slice.

## 3. Мапи (Maps) — аналог JS Map / об'єктів
Мапа — це невпорядкована колекція пар ключ-значення.

```go
m := map[string]int{
    "apple":  5,
    "banana": 3,
}

// Перевірка існування ключа (comma-ok idiom)
val, exists := m["banana"]
if exists {
    fmt.Println("Значення:", val)
}
```

> **Від JS:** `map[string]int{}` ≈ `Map<string, number>` або `{ [k: string]: number }`. 
> - Go map **невпорядкована** — як JS `Map` (не `Object`, який має властивості в insertion order).
> - Перевірка ключа через `v, ok := m[k]` ≈ `m.has(k)` або `k in obj`.
> - У Go не можна звернутися до неіснуючого ключа без перевірки — отримаєш zero-value (0, "", false), а не `undefined`.

## 4. Errors vs Exceptions
Go **не має try/catch**. Помилки повертаються як значення — це як повертати `[result, error]` tuple (як у Rust чи Go-ідиома):

```go
val, err := doSomething()
if err != nil {
    // обробка помилки (аналог catch)
}
```

> **Від JS:** JS кидає exception → `try/catch`. Go повертає `error` → перевірка `if err != nil`. Немає "кидання" — кожен виклик явно обробляє помилку. Це як у Rust `Result<T, E>` або JS-патерн `{ data, error } = await fetch()`.
>
> **Коли краще Go:** коли потрібен контроль над помилками на кожному кроці, уникнення "прихованих" throw. **Коли краще JS:** коли помилок мало і важлива швидкість написання коду.
